## 3. Current Post State Machine

`
queued
  |
cleaning          (SSH/gwr, background thread ~2-5 min)
  |
cleaned
  |
scheduled         (Gemini enrichment + slot assignment, ~5-15s in-tick)
  |  [no youtube_video_id]
uploading         (YouTube API, background thread ~1-3 min)
  |
scheduled         [now has youtube_video_id -- sheet writeback]
  |
uploaded          (comment posted)
  |              [instagram_enabled & past scheduled_at]
[instagram publish]

  --> failed (any stage, retry_count < max_retries --> re-queue)
`

PROBLEMS with current state machine:
- scheduled is used BOTH as enriched-waiting-to-upload AND uploaded-with-video_id-waiting-to-publish
- uploaded is set ONLY after first-comment
- State transitions scattered across 5+ files with no validator
- Any code can mutate status directly

## 4. Current Job Execution Flow

`
APScheduler (every 30s)
  -- run_serial_queue()
        |- Priority 1: queued --> clean_one_post(post_id)
        |    -- threading.Thread(watermark SSH + Drive upload)
        |- Priority 2: cleaned --> enrich_one_post(post_id)    [in-process Gemini]
        |- Priority 3: scheduled/no-vid --> threading.Thread(upload_one_post)
        |- Priority 4: uploaded --> comment_one_post(post_id)
        -- Priority 5: (Instagram runs as separate APScheduler job)

APScheduler (every 60s) -- run_instagram_publish_job()
APScheduler (daily 9:00 IST) -- run_asmr_workflow_job()
APScheduler (daily 9:05 IST, if FAL_API_KEY) -- run_auto_generate()
`

## 6. Critical Failure Modes

### CRITICAL (data loss / duplicate publish risk)
1. Worker dies mid-upload: YouTube accepts video but DB never gets video_id.
   Startup heuristic re-queues after 15min. RISK: duplicate upload on restart.
2. threading.Lock is per-process: multiple Render replicas can claim and upload same post simultaneously.
3. main.py lifespan spawns Drive upload threads for every post missing drive_file_id -- dozens of threads on restart.

### HIGH
4. Google Sheets called synchronously in upload path -- Sheets timeout = pipeline stall
5. Gemini call blocks APScheduler thread (5-15s in-tick) 
6. No circuit breaker on YouTube quota -- retry storms possible
7. Stateless JWT refresh tokens -- cannot be revoked server-side
8. Base.metadata.create_all() in production lifespan -- masks migration gaps

### MEDIUM
9. except Exception: pass patterns -- silent failures
10. _in_progress and _uploading sets lost on restart
11. Status string literals scattered across 6+ files -- no enum
12. No pagination on posts list
13. No rate limiting on login, upload, or API endpoints
14. No structured JSON logging

## 9. Migration Risk Register

| Risk | Severity | Mitigation |
|------|----------|------------|
| Redis requirement for workers | HIGH | Add Redis via Render managed |
| State machine changes breaking job selectors | HIGH | Gradual migration with compatibility |
| Removing create_all() | MEDIUM | Alembic baseline migration first |
| Separating web/worker processes | MEDIUM | Separate Render services |
| Sheets async-only | LOW | Already mostly non-blocking |
| Stateful refresh tokens | LOW | Add refresh_tokens table |
